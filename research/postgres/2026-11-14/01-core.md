# Core PostgreSQL changes since 2026-05-14

Research date: 2026-11-14. Skill baseline: written 2026-05-14 (covers PG14-18, PG16 default). All claims cite a primary source (postgresql.org, or the postgres source tree on GitHub for release-note revisions). Quotes are verbatim.

## Summary

- **PG14 is EOL.** Final release 14.25 on 2026-11-12: "This is the final release of PostgreSQL 14". Supported majors are now four: 15, 16, 17, 18. Our "five majors supported" claims are stale.
- **Current minors:** 18.7, 17.12, 16.16, 15.20, 14.25 (all 2026-11-12). Two minor rounds since 2026-05-14: 2026-08-13 (18.6/17.11/16.15/15.19/14.24) and 2026-11-12. **18.5 was never released** ("18.5 was not shipped due to a regression"), so 18.4 (2026-05-14) -> 18.6. Skill's table still shows 18.3/17.9/16.13/15.17/14.22 (Feb 2026).
- **PostgreSQL 19 has NOT shipped yet.** It is at RC 2 (2026-11-12); GA is planned for **2026-11-19** (5 days out), and `release-19.sgml` on REL_19_STABLE already stamps `2026-11-19`. Betas: B1 2026-06-04, B2 2026-07-16, B3 2026-08-13, B4 2026-09-24; RC1 2026-10-15.
- **Security:** Aug round fixed 28 CVEs, Nov round fixed 52 CVEs (many CVSS 8.8, arbitrary code execution). Several need user action: reindex (GIN, pg_trgm GiST, btree on `bpchar`, `btree_gist`, `ltree`, TOAST index after REINDEX CONCURRENTLY), take a new full backup if using incremental backups, add third-party logical-decoding plugins to the new `output_plugin_libraries` GUC, rebuild C extensions (new `composite_type_mismatch` GUC).
- **PG19 headline features:** `REPACK` (+ `CONCURRENTLY`), `pg_plan_advice`/`pg_stash_advice`, parallel autovacuum + autovacuum scoring, logical replication of sequences, `WAIT FOR LSN`, `effective_wal_level` (logical replication without restart), `COPY TO` JSON, `IGNORE NULLS`, `INSERT ... ON CONFLICT DO SELECT`, SNI via `pg_hosts.conf`, `pg_stat_lock`/`pg_stat_recovery`.
- **PG19 incompatibilities that contradict current skill text:** JIT off by default; `default_toast_compression` = `lz4`; `log_lock_waits` on by default; `max_locks_per_transaction` 64 -> 128; `io_workers` removed; RADIUS auth removed; `standard_conforming_strings` forced on; `wal_compression = on` now picks best method; wait events renamed; `sync_error_count` renamed.
- **Beta-1 announcement vs final:** several features the Beta 1 announcement (2026-06-04) advertised were **reverted before release** and are not in PG19: SQL/PGQ, `FOR PORTION OF`, `ALTER TABLE ... MERGE/SPLIT PARTITIONS`, `GROUP BY ALL`, online data checksums, `pg_get_{role,tablespace,database}_ddl()`. Do not document them as PG19.
- **Skill structure impact:** `100-pg-versions-features.md` needs a PG19 section and PG14-EOL rewrite; SKILL.md scope line (14-18, "PG16, 17, and 18") and PG14 "reaches end-of-life" claim are stale; ~10 topic files need PG19 admonitions.

### B. PG19 features touching existing topics

#### B1. REPACK command (replaces VACUUM FULL / CLUSTER surface)

- **What:** "Add `REPACK` command which replaces `VACUUM FULL` and `CLUSTER`... The old commands have been retained for compatibility." `REPACK ... CONCURRENTLY` "rebuild[s] tables without access-exclusive locking"; new GUC `max_repack_replication_slots`. Synopsis (https://www.postgresql.org/docs/19/sql-repack.html): `REPACK [ ( option [, ...] ) ] [ table_and_columns [ USING INDEX [ index_name ] ] ]`, options `VERBOSE`, `ANALYZE`, `CONCURRENTLY`; without a table name it processes every table the user has `MAINTAIN` on. New view `pg_stat_progress_repack` covers REPACK, CLUSTER, VACUUM FULL; `pg_stat_progress_cluster` is kept "for backwards-compatibility purposes only" and "will translate a REPACK command into CLUSTER" (https://www.postgresql.org/docs/19/progress-reporting.html). RC1 notes "Several fixes for `REPACK (CONCURRENTLY)`".
- **Where found:** #RELEASE-19-UTILITY, #RELEASE-19-SYSTEM-VIEWS; sql-repack and progress-reporting pages above.
- **Affects:** `26-index-maintenance.md:17, 63, 332-360, 652` (pg_repack/pg_squeeze are presented as the only online heap-reorg options; line 63 says REINDEX/VACUUM FULL "Avoid" and recommends pg_repack); `28-vacuum-autovacuum.md:50, 67, 109-127, 670` (VACUUM FULL section); `58-performance-diagnostics.md:43, 64, 93, 316-319, 669` and `82-monitoring.md:273` (VACUUM FULL/CLUSTER progress only in `pg_stat_progress_cluster`); `31-toast.md`, `30-hot-updates.md`, `62-tablespaces.md`, `67-cli-tools.md`, `88-corruption-recovery.md`, `102-skill-cookbook.md` mention VACUUM FULL / pg_repack.

#### B2. Autovacuum: parallel workers, scoring, new logging

- **What:** "Allow autovacuum to use parallel autovacuum workers"; `autovacuum_max_parallel_workers` and per-table storage parameter `autovacuum_parallel_workers`. "Add scoring system to control the order that tables are processed by autovacuum"; GUCs `autovacuum_freeze_score_weight`, `autovacuum_multixact_freeze_score_weight`, `autovacuum_vacuum_score_weight`, `autovacuum_vacuum_insert_score_weight`, `autovacuum_analyze_score_weight` (all present at https://www.postgresql.org/docs/19/runtime-config-vacuum.html). Table scans can "mark pages as all-visible in the visibility map" (previously only `VACUUM` and `COPY ... FREEZE`). Parallel vacuum change (incompatibility): "Change parallel vacuum leaders and workers to share the cost-based vacuum delay limit... `VACUUM` with parallel workers and cost-based delay enabled might run slower than in previous releases." `pg_stat_progress_vacuum` gains `started_by` and `mode`; `pg_stat_progress_analyze` gains `started_by`. XID/multixact wraparound warnings now at 100 million remaining (was 40 million). `pg_get_multixact_stats()` added. Verbose vacuum/autovacuum logs add memory usage, parallelism, and WAL full-page-write bytes.

#### B5. Replication: sequences, wal_level, WAIT, slot sync, retain_dead_tuples

- **What:** (a) Logical replication of sequences: `CREATE`/`ALTER PUBLICATION ... ALL SEQUENCES`; `ALTER SUBSCRIPTION ... REFRESH SEQUENCES`; sync occurs on `ALTER SUBSCRIPTION ... [ADD|SET|REFRESH|DROP] PUBLICATION`. (b) `CREATE`/`ALTER PUBLICATION ... EXCEPT` to exclude tables with `ALL TABLES`. (c) Subscription option `retain_dead_tuples` (+ `max_retention_duration`) for conflict detection; `pg_stat_subscription_stats.update_deleted` column. (d) `CREATE SUBSCRIPTION ... SERVER` using `postgres_fdw` connection params; `CREATE FOREIGN DATA WRAPPER ... CONNECTION`. (e) "When server variable `wal_level` is `replica`, allow automatic enablement of logical replication when needed"; new read-only `effective_wal_level` (also in `pg_controldata`, `pg_control_checkpoint()`); docs: "when `wal_level` is set to `replica` and the system has one or more logical replication slots, `effective_wal_level` will show `logical`". (f) `wal_receiver_timeout` settable per subscription and user. (g) `WAIT FOR LSN 'lsn' [ WITH ( MODE 'standby_replay|standby_write|standby_flush|primary_flush', TIMEOUT '...', NO_THROW ) ]` (https://www.postgresql.org/docs/19/sql-wait.html; the release notes call it "`WAIT` command"; sgml commit 2026-09-14 "Rename the WAIT FOR command to WAIT in the documentation"; page is `sql-wait.html`, `sql-wait-for.html` is 404). Default mode `standby_replay`. (h) `wal_sender_shutdown_timeout` ("By default, senders still wait forever"). (i) Slot sync skip columns `slotsync_skip_count`, `slotsync_last_skip`, `slotsync_skip_reason` in `pg_stat_replication_slots` and `pg_replication_slots`; `mem_exceeded_count` in `pg_stat_replication_slots`; `pg_sync_replication_slots()` now waits for completion. (j) `pg_stat_wal_receiver.status` gains `connecting`. (k) `pg_createsubscriber`: ignores already-existing publications; recovery params go to optional `pg_createsubscriber.conf`; `-l/--logdir`. (l) Incompat: `pg_stat_subscription_stats.sync_error_count` renamed `sync_table_error_count`; new `sync_seq_error_count`. (m) `COPY TO` on partitioned tables "also improves logical replication table synchronization". Messages from remote servers (replication, postgres_fdw, dblink) now use the local log format.
- **Where found:** #RELEASE-19-LOGICAL, #RELEASE-19-REPLICATION, #RELEASE-19-SYSTEM-VIEWS, #RELEASE-19-MIGRATION, #RELEASE-19-SERVER-APPS.
- **Affects:** `74-logical-replication.md:41` ("Sequence-state changes are NOT replicated"), `:343-375` per-version timeline, `:474-477` and `87-major-version-upgrade.md:236-239, 250` (manual `setval()` sequence sync at cutover; "Sequences not replicated"), `:531` (`sync_error_count` in recipe) and `58-performance-diagnostics.md:68, 303` (`sync_error_count`), `:289-310` GUCs; `33-wal.md:94 (wal_level), 604 (read-your-writes via remote_apply; add WAIT FOR LSN)`; `75-replication-slots.md:87, 289, 317, 409` (wal_level = logical required); `73-streaming-replication.md`, `77-standby-failover.md` (read-your-writes on standbys, `wal_sender_shutdown_timeout`); `76-logical-decoding.md`.

#### B6. Server defaults changed (breaking for stated defaults)

- **What (all quoted from #RELEASE-19-MIGRATION):**
  - "Change [JIT] to be disabled by default... This change requires sites that are doing many large analytical queries to manually enable JIT." Confirmed `jit (boolean)... The default is off.` at https://www.postgresql.org/docs/19/runtime-config-query.html.
  - "Change the default TOAST compression method from `pglz` to the more efficient `lz4`" (`default_toast_compression`; docs/19 runtime-config-client: "default is lz4").
  - "Change default of `max_locks_per_transaction` from 64 to 128... effectively settings must now be doubled to match their capacity in previous releases." (docs/19 runtime-config-locks: "default, 128").
  - "Enable server variable `log_lock_waits` by default" (docs/19 runtime-config-logging: "The default is on").
  - "Change `wal_compression` equals `on` to use the best WAL compression method available. Previously this always used `pglz`." docs/19: "The value `on` selects the first of zstd, lz4, pglz that is available. The default value is off."
  - "Remove server variable `io_workers`" replaced by `io_min_workers` (default 2), `io_max_workers` (default 8), `io_worker_idle_timeout` (default 1 minute), `io_worker_launch_interval` (default 100ms), verified at https://www.postgresql.org/docs/19/runtime-config-resource.html.

  - "Disallow carriage returns and line feeds in database, role, and tablespace names"; `pg_upgrade` refuses such clusters.
  - "Remove `MULE_INTERNAL` encoding".
  - `log_min_messages` now accepts `type: level` per process type; `password_expiration_warning_threshold` (default 7 days); `md5_password_warnings`: "Issue a warning after successful MD5 password authentication" (the GUC itself already existed in PG18 per our 48:555).
  - Server variables that are lists "can be emptied by setting the value to `NULL`".

GRANTED BY`; `CHECKPOINT (MODE ..., FLUSH_UNLOGGED)`.
